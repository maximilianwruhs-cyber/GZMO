# GZMO Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the missing corpus contract to GZMO, then create `maximilianwruhs-cyber/gzmo-demo`, a private deployment-only repository that prepares a verified USB bundle and installs a full, local GZMO living-memory demo on one Ubuntu 24.04 NVIDIA host.

**Architecture:** GZMO first gains a native corpus store, FTS+vector indexing, and explicit search-result labels, released as v0.1.15. The new repository then has an online bundle-building phase and a fail-closed offline installation phase. A committed JSON lock file pins that GZMO release, model files, and OCI image digests; small Bash modules provide shared lock, bundle, host, install, and report contracts.

**Tech Stack:** Bash 5, jq, curl, GNU coreutils, GitHub CLI, Docker Engine/Compose, systemd, plain Bash test harness, GitHub Actions

**Spec:** `docs/superpowers/specs/2026-08-20-gzmo-demo-design.md`

## Global Constraints

- Target repository is `maximilianwruhs-cyber/gzmo-demo`, private initially.
- Sole supported profile is exactly `ubuntu-24.04-nvidia-32gb`.
- GZMO remains one living product; this repository contains no reduced implementation or lite SKU.
- The core path makes no public network request on the lab host.
- Every published service endpoint binds to `127.0.0.1`.
- Exactly one GZMO daemon may own the living vault.
- Installation root is `/opt/gzmo-demo`; persistent state root is `/var/lib/gzmo`.
- A failed install must not change `/opt/gzmo-demo/current`.
- No model binary, secret, generated USB bundle, or GZMO source tree is committed.
- The demo must prove cited corpus recall, vector participation, normal-path verify/promote, and promoted-fact recall.

pool and creates `corpus_passages` plus an external-content

are `sha256:<file-content-sha256>:<zero-based-chunk-index>`. Upserts are
idempotent and update changed content without duplicating a passage.

- [ ] **Step 5: Implement `CorpusService::ingest_dir`**

The service accepts `.md` and `.txt`, sorts canonical paths, rejects files

`passages`, `fts_indexed`, and `vector_indexed`; any partial index failure
returns an error.

Create `scripts/lib/lock.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

lock_value() { jq -er --arg key "$2" '.[$key]' "$1"; }
artifact_rows() { jq -c '.artifacts[]' "$1"; }

validate_lock() {
  local lock="$1"
  jq -e '
    .schema == "gzmo.demo.bundle-lock/v1" and
    .profile == "ubuntu-24.04-nvidia-32gb" and
    (.bundle_id | type == "string" and length > 0) and
    (.artifacts | length == 6) and
    ([.artifacts[].id] | unique | length == 6) and
    (all(.artifacts[];
      (.id | type == "string" and length > 0) and
      ((.url | startswith("https://")) or (.url | startswith("docker://"))) and
      (.path | startswith("artifacts/")) and
      (.size | type == "number" and . > 0) and
      (.sha256 | test("^[0-9a-f]{64}$")) and
      (.license | type == "string" and length > 0)
    ))
  ' "$lock" >/dev/null
}
```

- [ ] **Step 3: Implement exact bundle verification**

Create `scripts/lib/bundle.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

verify_bundle() {
  local root="$1" lock="$2"
  [[ -f "$root/READY" ]] || return 1
  validate_lock "$lock" || return 1
  while IFS= read -r row; do
    local rel expected_size expected_sha file
    rel="$(jq -r '.path' <<<"$row")"
    expected_size="$(jq -r '.size' <<<"$row")"
    expected_sha="$(jq -r '.sha256' <<<"$row")"
    file="$root/$rel"
    [[ -f "$file" ]] || return 1
    [[ "$(stat -c '%s' "$file")" == "$expected_size" ]] || return 1
    [[ "$(sha256_file "$file")" == "$expected_sha" ]] || return 1
  done < <(artifact_rows "$lock")
}
```
